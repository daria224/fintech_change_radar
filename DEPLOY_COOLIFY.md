# Новое приложение Fintech Change Radar в Coolify

Эта инструкция создаёт **отдельное приложение** из репозитория `daria224/fintech_change_radar`. Существующий Desk Research AI Master в `dashaatea / production` не переключать и не редактировать. Его база `pgdata`, задача `collector`, Git Source, переменные и Telegram-маршрут остаются вне этого запуска.

## Изоляция по умолчанию

- Compose требует уникальный `RADAR_INSTANCE_ID`, например `prod-01`. Он задаёт отдельное Compose-имя и физическое имя тома `fintech-change-radar-<id>-postgres`.
- Сервис Radar создаёт свою PostgreSQL базу `fintech_radar` в томе с префиксом `fintech-change-radar-`. Мастер использует другое Compose-приложение, другое имя БД и свой том `pgdata`.
- Все секреты и настройки, которые задаются в Coolify, имеют префикс `RADAR_`. Compose передаёт их контейнерам под именами, которые ожидает приложение. Не подключайте Shared Variables от Master и не копируйте его значения.
- Telegram polling и OpenRouter выключены, пока их отдельные флаги не установлены в `true`. Ключи Radar по умолчанию пустые; наличие ключа само по себе не включает компонент.
- Расписание сбора работает внутри единственного worker Radar: каждые 6 часов. Не создавайте для Radar Scheduled Task `collector`; задача Master остаётся без изменений. Telegram-сводка работает только после отдельного включения Radar Telegram.
- Миграции создают необходимые таблицы в новой пустой базе. Они не читают базу Master и не требуют её таблиц или данных.
- Сборщик сохраняет все записи, которые возвращает текущий RSS/Atom источник (до настроенного лимита элементов на ленту). Старые строки из БД не удаляются по возрасту. `history_days=90` задаёт окно для сигналов, а не TTL хранения.

## Создание приложения

1. В Coolify добавьте **новый ресурс Application** в согласованном проекте, подключите GitHub-репозиторий `daria224/fintech_change_radar` и ветку `master`.
2. Выберите Docker Compose, Base Directory `/` и Compose File `/docker-compose.yml`. Не выбирайте существующий ресурс Desk Research AI Master и не нажимайте его Redeploy.
3. В Environment Variables **нового ресурса** задайте:

   | Переменная | Значение при первом запуске |
   |---|---|
   | `RADAR_INSTANCE_ID` | Уникальный slug, например `prod-01`; для каждого приложения на этом сервере свой |
   | `RADAR_POSTGRES_USER` | `radar_app` или отдельное имя |
   | `RADAR_POSTGRES_PASSWORD` | Новый случайный пароль только для Radar; используйте буквы и цифры, чтобы он безопасно помещался в PostgreSQL URL |
   | `RADAR_OPENROUTER_ENABLED` | `false` |
   | `RADAR_OPENROUTER_API_KEY` | Не задавать до отдельного решения о ключе, модели и бюджете |
   | `RADAR_MODEL` | Не задавать до выбора модели |
   | `RADAR_TELEGRAM_ENABLED` | `false` |
   | `RADAR_TELEGRAM_TOKEN` | Не задавать до миграции на отдельного бота и явного разрешения |
   | `RADAR_MINI_APP_URL` | HTTPS-домен ленты Radar; не домен Master |

   Не используйте `OPENROUTER_API_KEY`, `TELEGRAM_TOKEN`, `SERVICE_PASSWORD_POSTGRES` и другие переменные Master. Не помещайте секреты в Git, Compose-файл или `.env.example`.

4. Проверьте итоговый Compose до первого Deploy: имя проекта и том должны содержать `fintech-change-radar-<RADAR_INSTANCE_ID>`, БД — `fintech_radar`, флаги — `false`. Убедитесь, что у нового приложения отдельный домен и отсутствует Shared Variables Master.
5. Создайте новое приложение и проверьте его логи и `/health`. Без OpenRouter worker может собрать и сохранить исходные материалы, но не создаёт AI-карточки. Без Telegram polling не запускается. Никаких платных запросов этот первый запуск не должен выполнять.
6. Настройте и проверьте резервное копирование **нового тома Radar** до накопления ценных данных. Это настройка только нового ресурса; она не меняет отсутствие Storage Backups у Master.

## После отдельного решения об AI и Telegram

Сначала согласуйте провайдера/модель и бюджет, затем внесите отдельный `RADAR_OPENROUTER_API_KEY`, задайте выбранный `RADAR_MODEL` и явно включите `RADAR_OPENROUTER_ENABLED=true`. Код приложения ограничивает дневные расходы значением из `config/radar.json` (сейчас максимум $1); до изменения лимита сверить его с принятым бюджетом. Не запускайте исторический платный прогон без отдельного согласия.

Telegram включайте только после миграции существующего бота с Master на Radar и создания отдельного бота для Master. Тогда задайте только Radar-переменные `RADAR_TELEGRAM_TOKEN`, `RADAR_MINI_APP_URL` и `RADAR_TELEGRAM_ENABLED=true`. Пока флаг выключен, бот-сервис обслуживает HTTP-ленту, но не запускает Telegram polling, даже если токен случайно оказался в его окружении.

## Проверки и ограничения

- В `/health` и ленте должен отвечать только новый Radar.
- Проверьте, что новый ресурс показывает свой PostgreSQL-контейнер, БД `fintech_radar` и том `fintech-change-radar-<id>-postgres`; не подключайте том Master.
- Worker сам выполняет сбор с шестичасовым интервалом. Не добавляйте второе расписание сбора в Coolify.
- После включения Telegram отдельно проверьте `/start`, `/status`, доставку и ежедневную сводку около 09:00 МСК.
- После включения модели проверьте малую выборку, фактические цены и дневной лимит до обработки истории.
- У Master сейчас нет настроенного Coolify Storage Backup. Это остаётся отдельным риском для Master; данное развёртывание не должно затрагивать его базу.

Локальная конфигурация и безопасные значения приведены в [.env.example](.env.example). Инструкция здесь описывает подготовленный Compose, но сама по себе не подтверждает production-развёртывание.
