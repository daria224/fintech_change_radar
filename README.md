# Fintech Change Radar

Радар продуктовых изменений для команды российского розничного банка. Адаптация [desk-research-ai-public](https://github.com/vasilievyakov/desk-research-ai-public): Python, Postgres, OpenRouter и существующий Telegram-бот **@fintech_change_radar_desk_bot**.

```
10 RSS/Atom → материалы → предварительный отбор → текст статьи → OpenRouter
                                    ↓ резерв бюджета               ↓
                              Postgres ← события + основания → лента
                                              ↓
                                сводка в 09:00 МСК → подписчики
```

## Возможности

- Сбор каждые 6 часов внутри worker, блокировки от параллельных запусков.
- История до 60 дней из доступной части лент; первый сбор не рассылается как новости.
- Россия, СНГ, международный финтех и технологические компании. [Список наблюдения, источники и параметры](config/radar.json).
- Публикации объединяются в события. Общий сигнал требует разных событий разных компаний с одинаковой узкой механикой; перепечатки не создают второй сигнал.
- Карточка на русском: факты, значение для банка, гипотеза, ограничения, исследовательский вопрос, рекомендация и ссылки. Недоступный полный текст отмечается явно.
- До 5 событий и 1 общего сигнала в сводке. При отсутствии событий — короткий статус. Пробелы источников и очередь анализа показываются отдельно.
- Бюджет модели до $1 за день Москвы, включая историю. Резерв до запроса, контроль цены, учёт неясных исходов, перенос очереди. Стоимость сервера отдельно.
- Старые AI-находки доступны в `/archive`, подписчики и секреты сохраняются.

## Запуск

**Работать с компьютера:** [локальная инструкция](LOCAL_RUN.md). Откройте `SETUP_LOCAL.cmd`, затем `START_LOCAL.cmd`; для просмотра без ключей — `PREVIEW_LOCAL.cmd`. Локальная лента: http://127.0.0.1:18080/. Компьютер и Docker Desktop должны работать для сбора и сводок.

**Без GitHub:** подготовлены [самодостаточный Compose](deploy/no-github/compose.yaml) и [инструкция для интерфейса Coolify](deploy/no-github/README.md). Аккаунт GitHub и публикация образа в реестр не требуются. Автономный образ собран из пустого контекста; внутри прошли те же 27 тестов.

Python 3.12+ и Postgres 17. Установите `requirements.txt` в виртуальное окружение. Задайте переменные из [.env.example](.env.example) средствами окружения; файл `.env` автоматически не загружается. Не храните секреты в Git.

```text
python main.py worker
python main.py bot
```

Worker и bot — отдельные процессы. `bot` также обслуживает ленту на порту 8080; без `TELEGRAM_TOKEN` работает только HTTP-лента. Для Telegram-кнопки сохраните текущий HTTPS `MINI_APP_URL`. `web` предоставляет ту же ленту отдельным сервисом. `collector --history` запускает один ручной сбор истории.

Разовый ручной прогон сбора и обработки: `python main.py worker --once`. Он использует тот же бюджет и блокировки, что и постоянный worker.

В Coolify используйте существующее приложение с его базой и доменом. Сначала резервная копия, затем смена источника кода; подробная последовательность и откат — [DEPLOY_COOLIFY.md](DEPLOY_COOLIFY.md). Не создавайте второй экземпляр бота с прежним токеном.

## Проверка

```text
docker compose -f compose.test.yml up -d --wait
python scripts/run_checks.py
python scripts/check_live.py
python scripts/smoke_live.py
docker build -t fintech-change-radar:local .
```

`run_checks.py` и `smoke_live.py` используют **только** отдельную базу `radar_test` на `127.0.0.1:55432` и очищают её. Они не подключаются к рабочей базе. В `smoke_live.py` платный ключ удаляется из окружения перед проверкой анализа; Telegram не вызывается.

Результаты: [тесты](reports/tests.txt), [источники и извлечение](reports/live_sources.json), [реальный сбор и повтор](reports/live_collection.json). Автотесты проверяют ответы модели через подстановку; это не подтверждение качества живой модели. Проверка 20 реальных материалов моделью, чтение до 10 её карточек и первая доставка остаются обязательными при доступе к развёрнутому приложению.

## Ограничения пилота

RSS не гарантирует 60 дней или покрытие каждой компании. Нет магазинов приложений, Telegram и сложных парсеров. Сигналы сопоставляются консервативно по совпадающей формулировке механики; семантически похожие формулировки могут остаться ранними сигналами. Одно подтверждение выдержки не гарантирует точность всех выводов модели — карточки требуют проверки на пилоте.

Доставка хранится по каждому подписчику. После неоднозначного сетевого сбоя запись не отправляется автоматически повторно: это предотвращает дубли, но требует проверки недоставленных сообщений. Подробности — в инструкции развёртывания.
