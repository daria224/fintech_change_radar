# Запуск без аккаунта GitHub

Coolify умеет хранить Dockerfile или Docker Compose прямо в своём интерфейсе. Здесь подготовлен самодостаточный снимок кода радара: скачивать репозиторий для сборки не требуется. Серверу нужен обычный доступ к Docker Hub и PyPI для Python и зависимостей.

Проверено локально: Dockerfile собран из пустого контекста, внутри автономного образа прошли 27 тестов. Compose прошёл проверку синтаксиса Docker Compose. Развёртывание именно в вашем Coolify пока не выполнялось.

Файлы:

- `compose.yaml` — вся схема приложения: прежние сервисы `postgres`, `worker`, `bot`, том `pgdata` и код сборки внутри. Для ресурса типа **Docker Compose Empty / User-defined Service** это содержимое редактора **Edit Compose File**.
- `Dockerfile` — тот же код для ресурса **Dockerfile without Git**. Один образ поддерживает все роли; при раздельных приложениях нужны `BLOCK=worker` и `BLOCK=bot`. Это альтернативный путь: потребуется отдельно сохранить подключение к существующей базе и её сети.
- `manifest.json` — контрольные суммы включённых исходников. Внутри Dockerfile код упакован в архив; контрольная сумма проверяется при сборке. Ключи, токены, `.env`, подписчики и данные Postgres в пакет не входят.

## Если текущий ресурс — Docker Compose Empty

1. Откройте **свой существующий ресурс**. Сохраните его текущий Compose и настройки для отката. Сделайте резервную копию существующего Postgres; порядок описан в `../../DEPLOY_COOLIFY.md`.
2. Перед заменой сравните его сервисы и хранилище с подготовленным файлом. Не меняйте имя/тип/версию существующей базы или тома ради этого шаблона. Если действующая схема отличается от `postgres`, `worker`, `bot`, `pgdata` либо использует другой образ Postgres, сначала адаптируйте файл под неё.
3. В **Edit Compose File** вставьте содержимое `compose.yaml`. Действуйте в том же ресурсе: создание другого ресурса может создать отдельный пустой том.
4. Сохраните прежние `SERVICE_USER_POSTGRES`, `SERVICE_PASSWORD_POSTGRES`, `TELEGRAM_TOKEN`, `OPENROUTER_API_KEY`, домен bot и `MINI_APP_URL`. Значения задаются только в Coolify. `MODEL` — `openai/gpt-4.1-mini`.
5. Отключите прежние задачи по расписанию для collector. Новое расписание встроено в worker. Не запускайте второй экземпляр bot с тем же токеном.
6. Нажмите **Save**, затем **Deploy**. Проверьте логи, `/health`, `/status`, ленту и подписчиков. Дождитесь сводки в 09:00 МСК.

## Если ресурс подключён к Git или имеет другой тип

Не удаляйте его и не создавайте новую базу. Сначала нужно выбрать способ переноса настроек под фактический тип ресурса. Для выбора достаточно скриншота главной страницы/конфигурации ресурса без раздела с секретами. Ссылку на исходный публичный репозиторий можно оставить для отката, но в нём нет наших изменений.

## Последующие обновления

Исходники остаются локально в папке `radar`. После изменений команда `python scripts/package_without_github.py` пересоздаёт пакет. Новый текст Compose/Dockerfile нужно вставить в Coolify и выполнить Deploy. GitHub можно подключить позже; на работу бота отсутствие аккаунта не влияет.

Официальная документация: [Docker Compose в Coolify](https://coolify.io/docs/applications/builds/docker-compose), [способы развёртывания](https://coolify.io/docs/applications/choose-deployment-method).
