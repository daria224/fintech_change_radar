# Обновление только вашего Fintech Change Radar

Исходник: https://github.com/vasilievyakov/desk-research-ai-public. Рабочая копия адаптирована под существующего @fintech_change_radar_desk_bot. Новый токен и новый бот не нужны.

**Если аккаунта GitHub пока нет:** используйте [автономный пакет и инструкцию](deploy/no-github/README.md). Шаг создания собственного репозитория ниже для этого способа не нужен; резервная копия и сохранение прежнего ресурса обязательны для переноса данных.

## Перед обновлением

1. Создайте собственный репозиторий GitHub (или fork исходного), загрузите эту копию. В Git не должны попасть `.env`, дампы, ключи и пароли. Текущий remote исходника нельзя использовать для отправки изменений в чужой проект.
2. В Coolify откройте **только свой ресурс**, сверив имя проекта, домен ленты и имя бота. Сохраните текущий commit, источник кода, настройки сервисов, имя тома Postgres и число подписчиков. Общие настройки курса, другие ресурсы и сервер не меняйте.
3. Создайте резервную копию существующего Postgres средствами Coolify. Скачайте её в защищённое место; проверьте восстановление в отдельную временную базу. Альтернатива при доступном `pg_dump`: `python scripts/backup_database.py`. Скрипт берёт `DATABASE_URL` из окружения и создаёт новый файл `backups/*.dump`, не выводя пароль. Нужен `pg_dump` не ниже версии сервера. Без подтверждённой копии обновление не начинайте.
4. Остановите старые worker и bot **своего ресурса**. Отключите свои прежние cron / Scheduled Tasks, запускавшие `python main.py collector`. Новое расписание выполняется внутри worker. Проверьте, что второй экземпляр бота с тем же токеном не работает на другой платформе.

## Код и настройки

Переключите источник кода своего существующего приложения на свой GitHub-репозиторий и ветку с этим изменением. Не удаляйте ресурс, базу, том Postgres или домен. В Compose-приложении сохраните существующее имя проекта и том `pgdata`: новый ресурс с другим именем может создать пустую базу.

Сохраните существующие значения:

| Сервис | Переменные |
|---|---|
| worker | `BLOCK=worker`, прежний `DATABASE_URL`, прежний `OPENROUTER_API_KEY`, `MODEL=openai/gpt-4.1-mini` |
| bot | `BLOCK=bot`, `PORT=8080`, прежний `DATABASE_URL`, прежний `TELEGRAM_TOKEN`, прежний HTTPS `MINI_APP_URL` |
| web, если используется | `BLOCK=web`, `DATABASE_URL`, `PORT=8080` |

Значения ключей и токенов задавайте в Coolify, не в Git и не в чате. Модель можно менять: неизвестная цена или дополнительные обязательные сборы остановят платный анализ. Вызовы без известной цены не выполняются. Лимит приложения — $1 за календарный день Москвы, включая историю и ошибочные/неясные запросы. Сервер и иные приложения в этот лимит не входят. Дополнительный лимит самого ключа OpenRouter может служить общей защитой аккаунта.

Запустите Deploy. При старте любого блока миграции выполняются под блокировкой в транзакции. Таблицы `findings`, `materials`, `subscribers` и прежние записи сохраняются. AI-находки доступны через `/archive`, новый радар использует только `radar_events` и материалы с `radar_version`.

## Проверка после Deploy

1. В логах collector должны появиться результаты 10 источников. При первом сборе все доступные материалы помечаются историческими. Есть ручной запуск `python main.py collector --history`, но не включайте его постоянно в расписание.
2. Сбор выполняется в начале очередного шестичасового интервала UTC: 03:00, 09:00, 15:00 и 21:00 МСК; при первом старте — сразу. При перезапуске тот же интервал повторно не запускается. Сбой прерванного задания допускает повтор через 30 минут.
3. Worker должен создавать события и основания. Через `/status` проверьте бюджет, очередь и причины паузы. Пока отсутствует ключ или доступна только часть источников, сводка сообщает об этом. Очередь старше суточного бюджета будет разбираться в последующие дни.
   Для разового прогона используйте `python main.py worker --once`. Перед настройкой меню бот сверяет username с `bot_username` в конфигурации; токен другого бота не используется для рассылки.
4. Проверьте прежний адрес ленты и `/health`. В карточке нужны факты, значение для банка, гипотеза, ограничения, вопрос исследования, основание и режим текста. Если полный текст недоступен, это явно указано.
5. В личном чате существующего бота проверьте `/start`, `/status` и кнопку «Открыть ленту». Повторный `/start` не создаёт вторую подписку.
6. Проверьте 20 реальных материалов по отбору моделью и прочитайте до 10 полученных карточек. `reports/live_sample_review.json` проверяет только предварительный фильтр; это **не** оценка качества живой модели. До ключа OpenRouter проверена цепочка с подставленным ответом, а не реальным ответом модели.
7. В 09:00 МСК дождитесь первой сводки. В `radar_digests` должен быть один снимок дня, в `radar_deliveries` — отдельная строка на подписчика. История не рассылается. До пяти событий выбираются по применимости, новизне, основаниям и срочности, без добора до пяти.

## Неясная доставка и откат

Состояния `sending` после аварии и `uncertain` после сетевой ошибки не отправляются автоматически повторно: Telegram не даёт идемпотентный ключ `sendMessage`. Проверьте факт получения у конкретного подписчика. Только если сообщение не получено, вручную верните **его конкретную строку текущего дня** в `pending`. HTTP 429 допускает повтор, HTTP 403 выключает подписчика без удаления записи. Временная недоставка не заменяет успешную доставку всем остальным.

Если фактическая стоимость ответа превысила резерв, устанавливается `radar_meta.billing_pause`, блокирующий дальнейшие платные вызовы. Сначала проверьте тариф и учёт стоимости, затем снимите этот флаг вручную. Проверенные параметры `provider.max_price` и `usage.cost` описаны в [маршрутизации OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection#max-price) и [API ответа](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion). Без сведений о фактической цене сохраняется полный резерв запроса.

Для отката остановите свои bot и worker, верните прежний commit. Дополнительные таблицы можно оставить. Старые источники при миграции выключены; при откате восстановите их активность из сохранённого состояния. Не удаляйте новую историю для отката. Восстановление всей резервной копии выполняйте только при необходимости и с учётом новых подписок после копирования.

## Что ограничено в пилоте

RSS может показывать два дня, а не все 60. На каждой проверке записываются фактические минимальная/максимальная даты и ошибки источника. Нет отдельных парсеров, Telegram-каналов и магазинов приложений. Текст ограничен 14 000 символами; это явно ограничивает полноту анализа длинных статей. Общий сигнал формируется консервативно: не менее двух событий разных компаний с совпадающим узким описанием механики и различающимися выдержками. Разные формулировки одной механики могут остаться отдельными ранними сигналами. Дедупликация событий проверяется моделью по последним 35 событиям и устойчивому ключу; семантические пропуски требуют наблюдения в пилоте.
